## 一、被测范围与方法

### 1.1 测试维度

| 维度 | 说明 |

## 三、专项：对象级越权防护（任务模块）

### 3.1 测试设计

以 `admin` 的任务 `RUN-20261105-151234-6653` 为目标资源，使用 `eng1`（非属主）身份直接请求，验证横向越权。

### 3.2 结果

| 请求 | 身份 | 状态码 | 返回 | 判定 |
|---|---|---|---|---|
| `GET /review/tasks/RUN-20261105-151234-6653` | eng1 | **404** | 任务不存在 | ✅ 符合安全策略 |
| `GET /review/tasks/{id}/defects` | eng1 | **404** | 任务不存在 | ✅ 符合安全策略 |
| `GET /review/tasks/{id}/export` | eng1 | **404** | 任务不存在 | ✅ 符合安全策略 |

**结论**：对象级权限采用「统一 404、隐藏资源存在性」策略，有效防止 `task_id` 枚举与资源探测，与 G3-B D6 决策一致。

## 四、四层防护机制

| 层级 | 机制 | 本次验证情况 |
|---|---|---|
| 1 | 菜单按 `role` 显示/隐藏（`App.vue`） | ✅ eng1 仅见 2 项菜单 |

> 关键约束：前端守卫仅做体验拦截，**后端鉴权才是安全边界**。

## 五、缺陷清单

### 5.1 遗留缺陷

> **无。** 本轮未发现代码缺陷。

### 5.2 已撤销缺陷

**BUG-G3A-001（知识库接口 404）**

| 字段 | 内容 |
|---|---|
| 原始判断 | 后端未挂载 `knowledge_docs` / `knowledge_gaps` 的 `APIRouter`，定为 P1 阻塞 |
| 复测结果 | 后端路由表确认 `/api/v1/knowledge-docs`、`/api/v1/knowledge-gaps` 全部注册；`admin`（`X-User-Id: 3232`）请求返回 200 + 完整数据；前端 `knowledge.ts` 用 `request("/knowledge-docs")` 与 `http.ts` 的 `BASE_URL = "/api/v1"` 拼接正确 |
| 真实根因 | **测试报告笔误**：请求路径写成 `/api/knowledge-docs`（缺 `/v1`）；前端页面路由为 `/knowledge-base`（非 `/knowledge-docs`），访问 `/knowledge-docs` 命中的是前端 `/:pathMatch(.*)*` 兜底 404，不是后端 404 |
| 结论 | **非代码 bug，撤销** |

**原「菜单未隐藏」缺陷**

| 字段 | 内容 |
|---|---|
| 原始判断 | engineer 登录后顶部仍展示管理员专属菜单 |
| 复测结果 | 场景 4 无痕复测未复现，菜单裁剪正常 |
| 结论 | 旧会话残余登录态导致，**撤销** |

## 七、回归建议

1. 新增业务路由时必须统一挂载 `require_roles` 装饰器；
2. 新增菜单同步配套后端权限校验，保持前后端权限一致；
3. 迭代升级时重点回归对象级数据隔离（任务按创建人过滤）；
4. 测试报告登记状态码前，必须先在 Network 面板核对请求 URL 是否含 `/api/v1` 前缀；
5. 前端路由（如 `/knowledge-base`）与后端接口（`/api/v1/knowledge-docs`）需在用例中分开表述。
