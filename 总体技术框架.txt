1.总体技术框架
1.1 技术架构总体思路
本系统面向原理图智能评审、设计缺陷识别、专家辅助研判核心业务场景，构建 EDA 数据底座 + 确定性规则引擎 + AI 智能 Agent 三层协同的核心业务能力体系，以人工智能 Agent 能力为系统核心，采用 Python 原生 AI 技术栈构建整体架构。
整体业务分工边界清晰：
•EDA负责提供精准、可信的底层电路事实数据；
•规则引擎负责基于标准规范执行确定性、可解释的设计约束检查；
•AI Agent负责多源知识融合、复杂电路逻辑推演与专家级综合研判。
系统全链路打通EDA原生数据通道，依托EDA API接口完成工程数据标准化抽取，通过EDA Adapter将原始EDA数据转换为统一的 Schematic IR（原理图中间表示模型），形成面向电路语义的数据基础。
在此基础上，系统首先通过规则引擎完成电源、时钟、接口、参数等确定性强约束检查，再由AI Agent结合Schematic IR、电路规则结果、专业知识库和历史案例完成复杂缺陷推理，形成：
EDA事实输入 → Schematic IR结构化 → 规则确定性筛查 → AI深度智能研判
的分层评审闭环。
本系统所有核心流程、智能分析、知识库推理、任务编排均基于AI生态构建，整体架构轻量化、链路简洁，适配大模型本地部署与智能体持续迭代。
系统采用：前端展示 + 网关接入 + AI业务调度 + 技能组件封装 + 标准化工具服务 + 本地大模型推理的六层分层架构，完全匹配原理图分析、多维度评审、规则校验、复杂逻辑推理的AI原生业务特征，同时兼容EDA数据接入、Schematic IR转换、规则引擎联动校验和AI智能分析完整流程。
1.2 架构分层体系
系统自上而下分为六层，依次为：前端交互层、网关接入层、AI业务调度层、智能技能能力层、标准化工具服务层、大模型推理层，各层职责清晰、解耦彻底、可独立扩展。
系统内部通过EDA数据底座、Schematic IR模型、规则引擎和AI Agent形成协同体系：
•EDA数据底座负责原始电路事实获取；
•Schematic IR负责EDA数据统一语义建模；
•规则引擎负责确定性设计规范检查；
•AI Agent负责复杂逻辑推理和专家辅助研判。
1.2.1前端交互层
采用Vue前端框架构建专家操作界面，主要承担图纸上传、评审任务发起、缺陷结果展示、专家复核、知识库管理等交互功能。前端仅通过标准HTTP接口与后端通信，不参与任何AI计算与业务逻辑，实现前后端完全解耦。
1.2.2网关接入层
Nginx作为系统统一流量入口，负责静态资源托管、HTTPS统一证书管理、请求反向代理、限流防护、请求路由分发。所有前端请求统一经过Nginx转发至后端FastAPI服务，屏蔽后端真实服务地址，提升系统安全性、稳定性与可运维性。
1.2.3AI业务调度层
本层采用FastAPI + LangGraph为系统核心中枢，承担全部业务流程与智能任务调度，主要内容包括：
•用户请求管理；
•EDA数据处理流程调度；
•Skill调用编排；
•规则检查流程控制；
•AI推理任务调度；
•专家反馈流程管理。
FastAPI 提供高性能、标准化的后端接口服务，统一接收前端请求、管理会话、控制业务流程、输出标准化API能力，是整个AI系统的业务骨架，提供高性能标准化接口服务：
•接收前端请求；
•对接EDA平台API；
•管理任务状态；
•输出统一API能力。
LangGraph作为智能体流程编排引擎，负责完整评审任务DAG流程定义，通过调用不同Skill完成：
EDA数据获取→Schematic IR生成→规则引擎检查→RAG知识匹配→AI深度缺陷推理→专家经验沉淀
LangGraph主要负责：
•状态管理；
•分支控制；
•多Skill协同；
•多轮推理流程编排。
实现确定性规则能力和AI智能推理能力协同运行。
1.2.4智能技能能力层
本层集成多类Skill业务技能单元。Skill是面向具体业务场景的高内聚能力封装，通过组合MCP底层工具、规则服务和AI能力，为LangGraph提供可调用业务能力。Skill实现：业务流程、规则逻辑、底层工具三层解耦。
系统核心Skill包括：
1.原理图解析评审Skill
主要负责原理图工程数据获取和标准化转换，支持以下功能：
（1）本地Cadence工程解析；
（2） 通过EDA API接口远程获取工程数据。
通过EDA Adapter获取：
•元器件；
•管脚；
•网络；
•参数；
•属性；
•电路拓扑。
并将以上信息转换生成统一Schematic IR（原理图中间表示模型），Schematic IR以结构化JSON形式保存，包含：
•Design工程信息；
•Component元器件模型；
•Pin管脚模型；
•Net网络模型；
•Attribute属性；
•Hierarchy层级关系。
为规则检查和AI推理提供统一数据基础。
2.确定性规则校验Skill
负责调用独立规则引擎服务，规则引擎基于Schematic IR数据执行：
•电源设计检查；
•时钟设计检查；
•接口连接检查；
•器件参数检查；
•封装规范检查；
•安规设计检查。
检查输出结构化缺陷：
•问题位置；
•风险等级；
•规则依据；
•修改建议。
完成第一层确定性筛查。
3. 设计规范RAG检索Skill
该Skill基于以下内容：
•专业规范库；
•Datasheet；
•Reference Design；
•历史缺陷案例库。
执行知识检索，为AI深度推理提供专业上下文。
4. 缺陷根因分析Skill
该Skill融合以下内容：
•Schematic IR电路数据；
•规则检查结果；
•RAG知识结果。
调用本地大模型完成：
•隐性风险分析；
•多电路耦合推理；
•缺陷根因判断；
•优化建议生成。
5. 专家经验沉淀Skill
该skill负责专家反馈数据处理，主要内容包括：
•缺陷确认；
•误报标记；
•专家批注。
并根据专家审核结果，沉淀有效案例、形成规则优化建议、更新知识库，规则库调整需经过人工审核后生效，实现安全可控持续优化。
1.2.5标准化工具服务层
MCP（Model Context Protocol）作为模型上下文标准化协议，为Skill和Agent提供统一工具调用能力，系统通过独立MCP Server集群封装底层原子能力，包括：
•EDA API数据获取工具；
•Cadence数据读取工具；
•Schematic IR生成工具；
•Schematic IR查询工具；
•文件读写工具；
•规则库访问工具；
•向量数据库访问工具；
•通用数据存储工具。
其中，MCP负责提供原子工具能力：EDA接口、文件处理、数据转换、存储访问等；Skill负责解析能力、规则检查能力、AI分析能力；LangGraph负责整体业务流程调度，从而形成形成：MCP工具 → Skill能力 → Agent流程编排的分层调用体系。
1.2.6大模型推理层
基于vLLM搭建本地大模型高性能推理服务，专门承担所有AI推理、逻辑分析、文本生成、缺陷研判等大模型计算任务。vLLM独立部署、专注推理，不参与业务流程，保障模型推理速度与稳定性，支撑系统本地化、私有化部署需求。
模型输入包括：

•Schematic IR上下文；
•规则检查结果；
•专业规范知识；
•历史案例数据。
通过结构化事实数据和专业知识增强，实现专家级智能分析能力。
1.3 核心业务运行流程
业务流程的起点专家通过前端发起评审任务，发起方式包括：
（1）上传本地Cadence原理图工程；
（2）输入EDA工程编号，通过EDA API获取工程数据。
所有请求经过Nginx进入FastAPI服务，FastAPI完成以下功能：
•用户权限校验；
•任务创建；
•元数据保存；
•启动LangGraph评审流程。
第一步：EDA数据获取与Schematic IR生成
LangGraph调用EDA/原理图解析评审Skill，Skill调用MCP工具：本地文件解析工具和EDA API访问工具，获取：
•元器件；
•网络；
•管脚；
•参数；
•拓扑信息。
并通过EDA Adapter完成格式转换，生成Schematic IR统一结构化电路模型；Schematic IR保存至系统数据存储，并将必要摘要信息加载至Agent上下文。
第二步：规则引擎确定性检查
LangGraph调用确定性规则校验Skill，规则引擎读取Schematic IR，执行以下规则：
•电源规则；
•时钟规则；
•接口规则；
•参数规则；
•安规规则。
输出第一阶段确定性缺陷结果。
第三步：知识检索增强
调用设计规范RAG Skill，基于：
•电路结构；
•缺陷类型；
•元器件信息。
检索以下信息：
•设计规范；
•Datasheet；
•历史案例。
形成AI分析上下文。
第四步：AI深度智能研判
调用缺陷根因分析Skill。综合以下信息：
•Schematic IR；
•规则检查结果；
•专业知识；
•历史案例。
调用vLLM的LLM，完成以下内容：
•隐性风险分析；
•复杂逻辑推理；
•缺陷原因判断；
•优化方案生成。
第五步：结果融合与展示
LangGraph融合规则引擎确定性结果和AI推理结果，生成完整评审报告：
•缺陷位置；
•风险等级；
•判断依据；
•原因分析；
•优化建议。
结果返回FastAPI并展示。
第六步：专家反馈闭环
专家执行以下操作：
•确认；
•误报；
•批注；
•修改建议。
并反馈进入FastAPI，同时触发专家经验沉淀Skill，将专家经验沉淀为：
•有效缺陷案例；
•AI误判案例；
•规则优化建议。
经过人工审核后更新：
•规则库；
•向量知识库。
最终形成：EDA数据接入→Schematic IR结构化→规则确定性筛查→AI深度智能研判→专家复核→知识持续优化→完整智能原理图评审闭环。

1.4 架构设计优势
•AI原生架构，定位精准：系统以智能评审Agent为核心，而非传统业务系统外挂AI能力，完全匹配图纸评审AI产品属性；
•链路极简、无冗余层级：去除传统方案SpringBoot Java中转层，减少调用链路、降低故障风险与调试成本；
•分层清晰、模块化极强：MCP(工具)→Skill(业务能力)→LangGraph(流程编排)三层解耦，便于迭代、扩展、维护；
•技术栈统一、AI生态完整：全部采用Python AI原生技术栈，RAG、向量检索、Agent编排、模型适配性最优；
•完全支持私有化部署：所有服务可本地化部署，脱离公网、脱离开发IDE环境，满足工程落地要求；
•可无缝对接外部业务系统：如需对接现有Java业务平台，可通过独立接口层互通，不改动核心AI评审架构。
1.5 与传统Java主导架构的差异化说明
传统参考方案以SpringBoot Java体系为系统主体，AI服务仅作为外挂微服务承担辅助计算，适用于“已有成熟业务系统、叠加AI功能”的场景。
本项目为全新AI原生产品，核心价值、核心复杂度、核心迭代点全部集中在智能评审、知识推理、Agent任务编排，因此采用Python FastAPI+LangGraph架构作为系统主体，是更合理、更轻量化、更适配AI场景的技术选型。
